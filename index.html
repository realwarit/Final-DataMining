บทที่ 6

การประเมินผลและวัดประสิทธิภาพโมเดล 🎯

ประเมินโมเดลไปทำไม?

สร้างโมเดลเสร็จแล้วยังเอาไปใช้เลยไม่ได้ ต้อง พิสูจน์ด้วยตัวเลข ก่อนว่ามัน "แม่นยำ" และ "ถูกต้อง" พอจริงไหม เพราะงาน Data Mining เป็นหลักวิทยาศาสตร์และคณิตศาสตร์ ต้องวัดได้ พิสูจน์ได้

ตัววัดยอดนิยมของโมเดล Classification (การจำแนกประเภท) มี 4 ตัว:

Precisionความแม่นยำ · ดูทีละคลาส · เอา TP เทียบกับ FP
Recallความครบถ้วน (สไลด์เรียก "ความถูกต้อง") · ดูทีละคลาส · เอา TP เทียบกับ FN
F-measureรวม Precision และ Recall ไว้ในตัวเดียว · ดูทีละคลาส
Accuracyทายถูกกี่ % รวมทุกคลาส

คือ ตารางเทียบ "สิ่งที่โมเดลทาย" กับ "ความจริง (Ground Truth)" ว่าตรงกันมากน้อยแค่ไหน เป็นเครื่องมือหลักในการวัดโมเดล Classification ทุกตัววัดในบทนี้คำนวณจากตารางนี้

ความหมายแต่ละช่อง (ออกสอบบ่อยมาก!)

  • True Positive (TP) ทายว่าใช่ แล้วใช่จริง → Hit
  • True Negative (TN) ทายว่าไม่ใช่ แล้วไม่ใช่จริง → Correct Rejection
  • False Positive (FP) ทายว่าใช่ แต่จริง ๆ ไม่ใช่ → False Alarm, Type I error
  • False Negative (FN) ทายว่าไม่ใช่ แต่จริง ๆ ใช่ → Miss, Type II error
  • Condition Positive (P) = ของที่ "ใช่" ทั้งหมดในข้อมูล = TP + FN
  • Condition Negative (N) = ของที่ "ไม่ใช่" ทั้งหมดในข้อมูล = FP + TN
💡 ทริคจำคำหน้า (True/False) = ทายถูกหรือผิด · คำหลัง (Positive/Negative) = โมเดลทายว่าอะไร
เช่น False Negative = ทายว่า Negative แล้ว "ผิด" → แปลว่าความจริงคือ Positive

ตัวอย่างหมา–แมว 🐶🐱 (Positive = Dog)

  • หมา ถูกทายว่าหมา → TP
  • แมว ถูกทายว่าหมา → FP
  • หมา ถูกทายว่าแมว → FN
  • แมว ถูกทายว่าแมว → TN
⚠️ ระวังสไลด์ข้อความบรรยายบนสไลด์หน้าหมา–แมวสลับคำอธิบาย FP/FN กับรูป ให้ยึดตามตาราง/รูปภาพ (Predicted เป็นแถว Actual เป็นคอลัมน์) และนิยามด้านบนนี้

สูตรทั้ง 4 ตัว 📐

1) Precision · "ที่ทายว่าใช่ ถูกกี่ %"

Precision = TPTP + FPดูจาก "ผลการทำนาย" เป็นหลัก (แถว)

2) Recall · "ของจริงที่ใช่ เก็บมาได้ครบกี่ %"

Recall = TPTP + FNดูจาก "ผลเฉลย" เป็นหลัก (คอลัมน์)

3) Accuracy · "ทายถูกกี่ % แบบรวม ๆ"

Accuracy = TP + TNTP + TN + FP + FNดูรวมทุกคลาส = ผลรวมเส้นทแยง ÷ ทั้งหมด

4) F-measure · ค่าเฉลี่ยของ Precision กับ Recall

F = 2 × Precision × RecallPrecision + Recall(เป็นค่าเฉลี่ยแบบ Harmonic Mean — ถ้าตัวใดตัวหนึ่งต่ำ F จะต่ำตาม)
⚠️ สไลด์ขัดกันเองหน้า "ตัววัดประสิทธิภาพของโมเดล" เขียนว่า Accuracy พิจารณา "แยกทีละคลาส" แต่หน้าสูตร Accuracy เขียนว่า "พิจารณารวมทุกคลาส" → คำตอบที่ถูกคือ รวมทุกคลาส

Conditional Probability → Bayes Theorem 🧠

P(A|B) = P(A ∩ B)P(B)
  • P(A|B) conditional probability: B เกิดก่อน แล้ว A ตามมา
  • P(A ∩ B) joint probability: A และ B เกิดร่วมกัน
  • P(B) ความน่าจะเป็นที่ B เกิด

เพราะ P(A∩B) = P(A|B)×P(B) = P(B|A)×P(A) จัดรูปได้เป็น Bayes Theorem แล้วเปลี่ยนสัญลักษณ์เป็น A = attribute, C = class:

P(C|A) = P(A|C) × P(C)P(A)
Posterior · P(C|A)ความน่าจะเป็นที่ตามมา: ข้อมูลที่มี attribute A จะเป็นคลาส C
Likelihood · P(A|C)ความเป็นไปได้: ในข้อมูลเทรนคลาส C มี attribute A เท่าไร (A = a₁ ∩ a₂ ∩ … ∩ a_M)
Prior · P(C)ความน่าจะเป็นที่ทราบมาก่อน: สัดส่วนของคลาส C
P(A)ความน่าจะเป็นของเหตุการณ์ A (ทุกคลาสใช้ตัวหารเดียวกัน)
💡 ทำไมเรียก "Naïve" (ไร้เดียงสา)เพราะสมมติว่าแต่ละ attribute เป็นอิสระต่อกัน จึงเอา P(a₁|C) × P(a₂|C) × … มาคูณกันได้เลย
และเวลาเทียบคลาส ตัวหาร P(A) เท่ากันทุกคลาส จึงตัดทิ้งได้ (สไลด์ก็คำนวณแบบไม่หาร) ✂️

คำถามท้ายสไลด์ (เฉลย) ❓

คำถามท้ายสไลด์คิดจากตารางตรง ๆ (นับแถว) ได้เลย:

  1. โอกาสไปเล่นกอล์ฟตอนฝนตก: rainy มี 5 วัน เล่น 3 → 3/5 = 60%
  2. โอกาสไม่เล่นตอนฝนตก: 2/5 = 40%
  3. ความชื้นสูงแล้วไม่เล่น: high มี 7 วัน ไม่เล่น 4 → 4/7 ≈ 57.14%
  4. มีลมและแดดออก (sunny + windy=true) แล้วเล่น: มี 2 วัน (#2 no, #11 yes) → 1/2 = 50%

จากใบเสร็จสู่ Transaction Database 🧾

ข้อมูลจากใบเสร็จ (POS) ประกอบด้วย: รหัสการซื้อหนึ่งใบเสร็จ (Transaction ID) · ข้อมูลลักษณะลูกค้า · ปริมาณสินค้าที่ซื้อ · ข้อมูลประเภทสินค้าที่ขาย · จำนวนเงิน

แปลง POS database (1 แถว = 1 สินค้า) เป็น transaction database (1 แถว = 1 ตะกร้า) ด้วยการ Group by ตามเวลาที่ซื้อสินค้า

Itemset และจำนวนรูปแบบ 2ᴺ − 1 🔢

Item set = กลุ่มของสินค้าตั้งแต่ 1 ชนิดขึ้นไป เขียนแบบเซต เช่น {โยเกิร์ต} {นม, ผัก} {ขนมปัง, นม, โซดา}

จำนวน itemset ที่เป็นไปได้ = 2N − 1N = จำนวนชนิดสินค้า (−1 เพราะตัดเซตว่างออก)

สินค้า 3 ชนิด (Apple, Beer, Cereal) → 2³ − 1 = 7 รูปแบบ: ซื้ออย่างเดียว 3 แบบ · ซื้อ 2 อย่าง 3 แบบ · ซื้อ 3 อย่าง 1 แบบ

😵 The Problemร้านจริงมีสินค้าเป็นหมื่นชิ้น ถ้าคำนวณทุกรูปแบบด้วยมือ "เป็นไปไม่ได้" → จึงต้องใช้ Apriori คัดตัวที่ไม่บ่อยทิ้งไปเรื่อย ๆ

โครงสร้างของกฎ: LHS ⇒ RHS ➡️

  • LHS (Left-Hand Side) ส่วนซ้าย/ส่วนก่อน (Trigger) เช่น {ขนมปัง}
  • RHS (Right-Hand Side) ส่วนขวา/ส่วนหลัง (ผลที่ซื้อตาม) เช่น {เนย}

{ขนมปัง} ⇒ {เนย} แปลว่า ลูกค้าซื้อขนมปังแล้วจะซื้อเนยด้วย หรือพบเนยในตะกร้าที่มีขนมปัง

สร้างกฎจาก itemset ที่มีตั้งแต่ 2 ชนิดขึ้นไป โดยแบ่งสินค้าเป็นสองกลุ่ม (binary partition)

Support vs Confidence 📊

Support (ค่าสนับสนุน) · ความนิยมภาพรวม

Support(Itemset) = จำนวนทรานแซคชันที่ปรากฏจำนวนทรานแซคชันทั้งหมด (N)

Confidence (ค่าความเชื่อมั่น) · ความน่าเชื่อถือของกฎ

Confidence(LHS ⇒ RHS) = Support(LHS, RHS)Support(LHS)
SupportConfidence
วัดอะไรความนิยม (Popularity)ความน่าเชื่อถือ (Reliability/Probability)
ตอบคำถาม"สินค้านี้ถูกซื้อบ่อยแค่ไหนเทียบกับตะกร้าทั้งหมด""ถ้าซื้อ A แล้ว โอกาสซื้อ B ตามมามีเท่าไร"
เทียบกับทรานแซคชันทั้งหมดเฉพาะตะกร้าที่มี LHS
  • Minimum Support และ Minimum Confidence กำหนดโดยผู้เชี่ยวชาญ (Expert user) ขึ้นกับโจทย์ปัญหาและประสบการณ์
  • Confidence = 100% หมายถึง ซื้ออย่างแรก ต้องซื้ออย่างหลังเสมอ
  • กฎที่ดีต้องผ่าน ทั้ง Minimum Support และ Minimum Confidence
  • สไลด์กล่าวถึงตัววัดอีกตัวคือ lift ด้วย
⚠️ สลับข้างแล้วค่าเปลี่ยน!Confidence(A⇒B) ≠ Confidence(B⇒A) เพราะตัวหารคือ Support ของ LHS ซึ่งต่างกัน (แต่ Support ของทั้งคู่เท่ากัน)

Apriori: 2 ขั้นตอนใหญ่ ⚙️

หา frequent itemsets — รูปแบบที่เกิดร่วมกันบ่อย ≥ minimum support มี 2 ขั้นย่อย:
• Join สร้าง itemset ที่ยาวขึ้นทีละ 1 จาก itemset ที่ผ่านเกณฑ์
• Count นับค่า support แล้วตัดตัวที่ไม่ผ่านทิ้ง
สร้าง association rule — จาก frequent itemsets แล้วกรองด้วย minimum confidence เช่น Apple ⇒ Cereal
